# Handoff: GrepThink Analytics (one dashboard per institution)

**Brief:** `docs/superpowers/handoffs/2026-10-05-analytics-claude-design/README.md` (2026-10-05, revised 2026-10-06) + the 2026-10-07 revision block · **Companion spec:** `docs/superpowers/specs/2026-10-05-analytics-dashboard-design.md` · **Decisions, §9 answers and the palette report:** `NOTES.md` (this folder).

## Overview
`/app/analytics` — signed in, inside the app shell, instructors and maintainers only (students get the forbidden page). One dashboard per institution; the filter row narrows to a class and a date range; every card re-renders against the same slice of **one payload** (`AnalyticsDashboard`, brief §5). Reading order follows the brief's seven questions: activity tiles → conversations → (timeliness, sub-project C) → live scrum snapshot with stories/tasks created and characters per item → trends → breakdown. The first release ships without the timeliness pieces; the screen file shows both.

## About the design files
Design references created in HTML — intended look and behavior, not production code to copy. Recreate in the grepthink2.0 codebase (React 19 + TS + SCSS + Vite + Supabase) with its patterns: BEM SCSS classes **named exactly as listed in the revision block**, `--gt-*` custom properties, lucide-react icons, `useTableSort`, `Skeleton`, `DatePickerField`, the `Popover` primitive. The JSX in `../components/analytics/` is close to production shape (typed props in sibling `.d.ts`) — port it, don't import it. Charts are hand-rolled SVG whose colors come from a series-identity class (`.gt-series--1…4`, `.gt-series--gray`, `.gt-status--*`) bound to registered tokens (`--gt-series-*`, `--gt-status-*`); marks paint with `currentColor` here, or `var(--series)` in the codebase form — the `BurnupChart` idiom. `analytics.css` contains **no raw hex**, so it passes `lint:design` as-is.

## Fidelity
**High-fidelity.** Colors, type, spacing, radii, states, copy and chart rules are final and token-exact. Throwaway scaffolding: `ui_kits/grepthink/analyticsData.js` (the two sample payloads + a deterministic per-class derivation), `analyticsSrcLoader.js` (renders the family from source when the compiled bundle is stale) and the floating "Demo" control bar (state · release · width).

## Screens (`ui_kits/grepthink/analytics.html`)
- **Layout:** app shell (256px green sidebar, **Analytics** in *Main* after Create Class) → content `padding: 20px 24px` → `.gt-analytics` (max-width 1400, container-queried): header → filter row → tiles (5/6 → 3 → 2 columns at 1200/640) → `__grid` (two columns, one below 1000) → footnote. `.gt-chart-card--wide` spans both columns (Scrum, Trends, By class; Conversations in the first release).
- **States (Demo bar):** filled (`sample-data.json`) · empty (`sample-data.empty.json`: "—" tiles with hints, empty cards, `failures: ['scrum']` → error strip + Retry) · loading (skeleton tiles and cards, filters disabled) · refetching (every card body at 60% opacity, frame held) · forbidden (`.gt-analytics__forbidden`). Release: first / + timeliness. Width: desktop / 1000 / phone (sidebar hidden; tables scroll inside their card).
- **Interactions:** range chips and class select (→ per-assignment timeliness incl. a not-due row, per-team breakdown with Members, `SplitBar` flips to mixed scope, subtitles gain "· CSE 115A · Fall 2026"); Custom popover; Refresh and any filter change simulate an 800 ms refetch; Tasks | Points; Compare checkbox (disabled on All, which has no previous range); Table twins; legend isolation; keyboard focus shows the hover tooltip on every mark; Export CSV downloads the breakdown; View drills down.
- The privacy footnote "Aggregates only. No individual student is identified on this page. Groups of fewer than 3 are combined." is on every state, including forbidden.

## Interactions & behavior
- Filter changes re-request one payload; the frame is held (`data-state="refetching"`) until it lands — no skeleton after the first load. Refresh forces a fresh fetch the same way.
- Range chips are `aria-pressed`; "Class to date" needs a class; Custom's Apply is disabled while the dates are invalid and the panel's last row (`.gt-filter__foot` › `.gt-filter__reason`, `role="status"`) says why: "Dates must fall between 2000 and 2100" · "A range may span at most 2 years" · "To must be on or after From"; the popover closes on Esc / outside click / Apply.
- A failed request keeps the previous payload on screen and shows the page's one alert, `.gt-analytics__error` (`role="alert"`, error-soft strip under the filter row): "The latest request failed (HTTP n)." · for a refused request (4xx) "The latest request failed: " + the backend's reason · "The server could not be reached." — each followed by " Showing the previous figures." while an earlier payload stays on screen. Any count that arrives `null` reads "—" (table cell) or "—" + "Could not load" (tile, `failed`); the card is listed in `failures`.
- Trends draw only complete weeks (`completeWeeks(points, asOf)`: Monday-start week whose Sunday ≤ `as_of`); the week in progress appears once it ends. Tile sparklines follow the same rule (the data layer passes complete weeks only). Three empty states: "Trends appear after the first nightly rollup." (no rollup) · "No complete week in this range yet." · "No team activity in this range." (all values null/0). The Trends and Scrum cards each have a Table toggle (`.gt-analytics__toggle` › `ChartCardTool`); the Trends compare checkbox is `.gt-analytics__check` › `ChartCardCheck`.
- Table toggles are real buttons with `aria-pressed`; every chart has `role="img"` + `aria-label` summary; marks are focusable (2px accent ring) and show the hover tooltip on focus; legend items toggle with `aria-pressed` and isolate a series; the unit toggle moves with ← →.
- All transitions 0.2s ease (`filter: brightness(1.08)` on hovered marks); under `prefers-reduced-motion` nothing animates.
- Read-only surface: identical in "View class as student" preview.

## State management
- URL: `institution`, `class`, `range` (`preset`, `from`, `to`). Local: `unit` (`count | points`), `compare`, per-card `view` (`chart | table`), table `sort` (`useTableSort`), `refetching`, `failures` from the payload.
- Data: one `AnalyticsDashboard` payload per filter change (60 s server cache, `meta.cached`). Components take slices; the only client-side derivations are `fmtRange(meta.range.previous_*)` for delta labels and `meta.range.preset === 'all'` → no previous range (compare disabled, no deltas).
- Timeliness arrives empty (`on_time_rate: null`, `rows: []`) until sub-project C; the page hides that card, tile, panel and columns when the feature flag is off, and renders the empty/null states when it is on with no deadlines.
