# Handoff: Team meetings (Edit Project → Meetings tab + the project-page card)

**Brief:** maintainer prompt, 2026-10-18 ("Team meetings" section for project settings: a team's one-off meetings, PO-only editing in a new Edit Project tab, a read-only card on the project page, kind `meeting` in the schedule and calendar feed) · **Decisions and open questions:** `NOTES.md` (this folder) · **Builds on:** `design_handoff_schedule/` (ScheduleItem rows, kind palette, time-zone rule).

## Overview
Two surfaces, one data set. **Meetings tab** — a third tab in the existing Edit Project modal (Details · Team · **Meetings**), shown only to the team's Product Owner: upcoming meetings first, "Past (n)" collapsed, Edit / Delete per row, "Add meeting" opens the form inline above the list, Edit replaces the row with the same form, Delete confirms inline. Each meeting saves on its own (no "Save Changes" round-trip). **Team meetings card** — on the project page for every member, in the aside between Sprint progress and Roles needed: upcoming meetings as compact `ScheduleItem` rows (kind `meeting`, MEETING eyebrow, info tint) grouped by day, "Past meetings (n)" collapsed. Members see the card once a meeting exists; the Product Owner also sees it empty, as one quiet line ("No team meetings yet. Add one").

## About the design files
Design references in HTML/JSX — intended look and behavior, not production code to copy. Recreate in grepthink2.0 (React 19 + TS + SCSS + Vite + Supabase) with its patterns: BEM SCSS, `--gt-*` custom properties, lucide-react icons (`CalendarDays` tab icon, `CalendarPlus`, `Users`, `MapPin`, `Video`, `ChevronRight`, `CircleAlert`, `RefreshCw`, `Globe`, `ArrowRight`). `../components/domain/TeamMeetingsList.jsx`, `TeamMeetingForm.jsx` are close to production shape (typed props in the sibling `.d.ts`); `TeamMeetingsModel.jsx` is pure logic and ports as `features/project/teamMeetingsModel.ts`. Styles are the `.gt-tm*` / `.gt-tmform*` blocks at the end of `../components/domain/domain.css` — **no raw hex** (lint:design); the kind color is the schedule layer's `--gt-sched-meeting-soft/-text` pair.

## Interactions & keyboard
Tab order in the tab: Add meeting → each upcoming row's Zoom link, Edit, Delete → Past (n) → past rows → the modal footer. Add / Edit open the form and focus Title; Enter in any text field submits; Esc cancels the form (not the modal). Delete opens the confirm with focus on Cancel; Enter on Delete deletes; Esc cancels. While a form is open, Add and every other Edit / Delete are disabled (one editor at a time). After a save the form closes, the row re-sorts into place, the live region announces. The card's Zoom / Join Zoom follow the schedule layer (`onJoin` for analytics). No drag, no hover-only affordances.

## Data contract
```
TeamMeeting { id, projectId, title (≤ 80), startsAt (ISO instant), durationMinutes (15-min steps, default 60),
              location (string | null), zoomUrl (https URL | null), note (≤ 500 | null), createdBy (user id), updatedAt }
Form payload (onCreate / onUpdate): { title, startsAt, durationMinutes, location, zoomUrl, note }
Schedule feed: toScheduleItem(m, { teamName, people }) → ScheduleItemData kind 'meeting', endsAt = startsAt + duration,
              scope 'team', host = createdBy as Organizer, note; the agenda / compact card / ICS feed consume it unchanged.
```
Proposed storage: `team_meetings` (`id`, `project_id` → projects, `title`, `starts_at timestamptz`, `duration_minutes int check (duration_minutes % 15 = 0)`, `location text`, `zoom_url text`, `note text`, `created_by` → users, `created_at`, `updated_at`) — or the `class_events` table proposed in `design_handoff_schedule/NOTES.md` with `kind = 'meeting'`, `scope = 'team'`, `project_id` set (one table for every schedule kind; see `NOTES.md` here). Endpoints: `GET /api/projects/:id/meetings` (members), `POST /api/projects/:id/meetings`, `PATCH /api/meetings/:id`, `DELETE /api/meetings/:id` (Product Owner; RLS on `project_members.project_role = 'product owner'`). `GET /api/schedule` includes them as kind `meeting` for every member of the project.
