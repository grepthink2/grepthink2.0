# Notes — What's new (release notes), 2026-10-23

## 1. Answers to brief §12
1. **The "New" marker and the group labels.** The marker is the kit's Badge in a new small size — `<Badge status="release.new" size="sm" />`: a blue soft pill ("New", 11px, `2px 8px`) in the entry's heading row, after the version; informational blue under the status rule, so it cannot be mistaken for the red UnreadBadge. The group labels are plain caps headings (`h4`, 11/600, `--gt-tracking-wide`, tertiary) above their lists, with no fill, no dot and no rule. A pill in the heading row and a caps label over a list never read alike, so an entry can carry both. In the dark modal the marker takes the dark variant's translucent blue (`--gt-dark-accent-soft` / `--gt-dark-accent-text`).
2. **The dot.** `NewDot`: 8px, `--gt-new-dot` = `--gt-info` (#2771FF) in both contexts — 4.3:1 on the white app header, 4.0:1 on the landing's dark bar (a graphical object needs 3:1). On the **avatar** it sits at the top-right (`top: -1px; right: -1px` of the 28px disc) with a 2px white ring (`--gt-new-dot-ring` = `--gt-surface`), so it stays a dot over a photo, initials or the user icon. On the **landing tab** it sits on the Info icon's top-right corner (`top: -3px; right: -4px`) with the ring re-coloured to the bar's dark from the header's own class (the pill is 82% of the same dark, so the ring reads the same there). One colour in both contexts, the ring takes the surface behind.
3. **Icon alone below 400px; the other items keep their size.** At ≤ 400px the nav is already 11px text; with the label the row needs ~413px, so the label goes there and the icon stands alone (`aria-label` keeps the name). At 401–560px the label shows and Features is hidden (the code's rule, now in `LandingHeader`). To fit 320px the pill's margins thin at ≤ 400px and the logo, gaps and buttons tighten at ≤ 360px (README §2); measured at 560, 400, 375, 360 and 320, in the bar and the pill: no overflow. The other items stay ~30px tall; the tab's 44px target is a centred `::after` hit area that reaches past its visible edge, as the brief allows. Growing the three essentials to 44px would make the pill 14px taller on every phone for a header that is mostly scrolled past — left as they are.
4. **The "School" label.** A `MenuGroup`: a caps label (10.5/600, `--gt-tracking-wide`, tertiary, `8px 10px 4px`) over the radio rows, `role="group"` named by it, followed by a `MenuSeparator` before the action rows. The label is needed: without it two school names at the top of the menu read as destinations, not a choice. The radio rows are the kit's (`menuitemradio`, the check slot on the current one).
5. **Size and phones.** `md` (560px): the reference's one-column rhythm, and 13.5px lines wrap at a comfortable length. Phones use the kit's layout — 12px margins, `max-height: calc(100vh - 24px)`, the head ("What's new", "Version 0.92.0", the ×) pinned while the feed scrolls under it; the body has `overscroll-behavior: contain` (added to the kit's `.gt-modal__body`), so a long feed's end never scrolls the page behind the lock. No footer, so nothing covers the last line.
6. **Names.** `WhatsNewModal` (the frame), `ReleaseFeed` (the body and its states — the lazy chunk), `ReleaseEntry` (one release), `ReleasesModel` (the design-side mirror of `version.ts` / `releaseNotes.ts` / `releaseDate.ts` / the seen rules), `WhatsNewTab` (exported from `LandingHeader.jsx`; the code's `WhatsNewTab.tsx`), `ProfileMenu` (`navigation/`, the code's `Layout/ProfileMenu.tsx`), `NewDot`, `MenuGroup`, `MenuItem trailing`, `Modal tone`, `Badge size` + `release.new`. CSS blocks: `.gt-whats-new`, `.gt-release-feed`, `.gt-release`, `.gt-landing-header__tab`, `.gt-profile-menu`, `.gt-new-dot`, `.gt-menu__group` / `__heading` / `__trailing`, `.gt-modal--dark`. The spec's provisional names were kept where they fit.

## 3. Decisions made in this round
- **A separator after the School group** (not in the brief's row list): two school names, then "View class as student" with no rule between them read as one list. The brief's own separator before "Log Out" stays.
- **The marker is a Badge, in a new `sm` size**, rather than a hand-built pill: the acceptance rule ("no hand-built badge") and the standard 27px Badge being too tall for a 15px heading row or a 32px menu row.
- **The failed state's Reload is primary** (`Button size="sm"`): it is the only action in the modal, and a primary button reads the same on the dark sheet without an outline variant for dark.
- **The seen state never moves the markers while the modal is up**: the hosts pass the `lastSeen` they opened with (`ui_kits/grepthink/WhatsNewScreen.jsx` shows the pattern; the demo bar's "Modal: open" counts as an opening).
- **The profile menu returns focus to the button only when focus would otherwise be lost** (Esc, a pick, the menu unmounting under the focused row) — an outside click leaves focus where the user put it. Tabbing out closes the menu (`onBlur` with `relatedTarget` outside).
- **`MenuItem`'s trailing marker is `aria-hidden`** and the row is described by the shared "New release notes", so the row's name stays "What's new" (the brief: names never change).
- **The landing header's layer** drops to `--gt-z-sidebar` (99) from `--gt-z-tooltip` (1000) — see §5.
- **Sample data**: the brief's three notes verbatim, un-wrapped onto one line per bullet (the kit's MarkdownText splits on newlines). Two invented entries (0.92.1, 0.93.0) exist only for the five-entries and long-entry states.

## 5. Where the brief and the checkout disagreed
The checkout read was the `gifted-williams-2c8524` worktree (the docs branch onto `beta` at `4376d1dd`).
- **`Header.scss` (landing) puts the header at `$z-index-tooltip` (1000).** The kit's Modal is `--gt-z-modal` (100), so a modal opened from the tab rendered *under* the header. The design moves the header to `--gt-z-sidebar` (99, the chrome layer, above the page and below modals); PR B ports it with the tab. The toast stack (1000) still sits above both.
- `Header.scss` (landing) has the 560px Features rule the design lacked; it is in `marketing.css` now, on `.gt-landing-header__link--features` (`links[].hideOnPhone` sets the class).
- `Header.tsx` (app) still renders the hand-built dropdown and `SchoolSwitcher`; the design's `ProfileMenu` replaces both, as the brief says. Labels are today's ("View class as student", "Instructor view", "Settings", "Log Out").
- The app's `Header.scss` profile button is `6px 12px`, white, the card shadow, radius `$border-radius-sm`, a 28px `.app-header__profile-icon` disc on the canvas colour — `.gt-profile-menu__button` keeps those values.
- Nothing else conflicted: the kit's Modal, Popover, Menu (`radio`, `autoFocus`) and Badge are as the brief describes.

## 6. Questions for the port
1. **The `lastSeen` snapshot.** The design keeps it in the host (`useWhatsNew` returns `lastSeenAtOpen`). If `useWhatsNew()` in the codebase returns only `{ unseen, lastSeen }`, `WhatsNewModal`'s host should capture `lastSeen` before calling `openWhatsNew()`, or the hook should expose the value it opened with.
2. **`MarkdownText variant="compact"`** — the design's `.gt-md` has one size; `releases.scss` sets 13.5px / 1.55 from `.gt-release__group .gt-md`. If `compact` sets its own size, the feature's rule should still win (it is more specific), but check the line height.
3. **`NewDot` has no words of its own.** Its hosts carry the hidden "New release notes"; if a future host wants the dot to speak for itself, add a `label` prop then, not now.
4. **Prefetch** the feed on hover / focus of the landing tab and when the profile menu opens — the design has no hook for it; `WhatsNewTab` forwards native props (`onPointerEnter`, `onFocus`), and `ProfileMenu`'s open state is internal (expose `onOpenChange` if the port needs it).
5. **The dark scrollbar.** `.gt-modal--dark` sets `color-scheme: dark` so the body's native scrollbar is dark; it also flips form controls inside, of which the modal has none. Drop it if a dark modal ever holds a field.
